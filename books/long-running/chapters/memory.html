Chapter 04

외부 기억: 진행 파일과 노트

교대 근무하는 간호사는 기억력이 아니라 인수인계 기록으로 환자를 이어 본다. 장기 실행 에이전트도 같다. 새 세션은 아무것도 모른 채 깨어난다. 무엇을 했고, 무엇이 남았고, 무엇을 시도했다가 실패했는지를 알려 주는 것은 창 밖의 파일뿐이다. 이 장에서는 외부 기억의 세 가지 형태 — 자유 서술 진행 파일, 구조화된 기능 목록, git 기록 — 와 그것을 오래 믿을 수 있게 유지하는 규칙을 본다.

  • 인수인계의 질이 세션마다의 재적응 비용과 중복 작업을 어떻게 바꾸는지 모형으로 설명할 수 있다.
  • 기능 목록을 에이전트가 함부로 고치지 못하게 하는 규칙과 그 이유를 말할 수 있다.
  • 코드가 바뀌면 노트가 낡는다는 점을 이해하고, 노트를 최신으로 유지하는 방법을 고를 수 있다.

기억상실 세션의 재적응 비용

새 세션이 처음 몇 턴을 쓰는 일은 늘 같다. “여기가 어디지? 무엇이 끝났지? 다음은 뭐지?” 이것이 재적응 비용re-orientation cost이다. 인수인계가 없으면 에이전트는 코드를 처음부터 읽어 상태를 추측한다. 프로젝트가 커질수록 이 비용도 커진다. 더 나쁜 것은 잘못 추측하는 것이다. 이미 끝난 기능을 다시 만들거나, 반쯤 된 기능을 끝났다고 여긴다.

인수인계 없음코드와 디렉터리를 뒤져 상태를 추측한다. 재적응 비용이 프로젝트 크기에 비례해 늘고, 중복 작업이 잦다.
자유 서술 노트progress.md에 지난 세션이 한 일을 적는다. 훨씬 낫지만 형식이 들쭉날쭉하고, 무엇이 “끝났는지”의 판단이 모호하다.
구조화된 기억features.json(기능마다 passes), progress.md(최근 세션 요약), git log(정확한 변경 기록). 몇 턴 만에 정확히 이어 간다.

모형: 재적응 비용은 없음 = 6턴 + (끝낸 기능 수 × 탐색 비용 증가), 자유 서술 = 8턴 + 그 값의 15%, 구조화 = 4턴. 잘못 추측해 이미 한 일을 다시 할 확률은 기능마다 20% · 6% · 1%. 해볼 것: ① 기본값에서 인수인계 없는 실행은 프로젝트가 커질수록 거의 멈춘다. 세션 대부분을 “어디까지 했더라”에 쓴다. ② 탐색 비용 증가를 0으로 내리면(작은 프로젝트) 차이가 줄어든다. 외부 기억의 가치는 프로젝트 크기와 함께 자란다. ③ 세션당 턴을 200으로 올려도 순서는 바뀌지 않는다. 큰 창이 인수인계를 대신하지 못한다.

기능 목록은 계약서다

기능 목록은 에이전트의 할 일 목록이자 완료의 정의다. 그런데 에이전트가 이 목록을 마음대로 고칠 수 있다면? 어려운 기능을 지우거나, 확인 단계를 빼거나, 테스트 없이 통과로 표시할 수 있다. 목록이 쉬워지면 “다 끝났다”도 쉬워진다. 그래서 규칙은 단순하다. 에이전트가 바꿀 수 있는 것은 passes 필드뿐이고, 그것도 실제로 확인한 뒤에만. 앞의 하네스 사례에서 Anthropic은 이 파일을 마크다운이 아닌 JSON으로 두었는데, 모델이 JSON 파일은 마크다운보다 덜 함부로 고쳐 쓰는 경향이 있었기 때문이라고 설명했다.

노트는 낡는다

진행 파일과 아키텍처 노트는 쓰는 순간부터 낡기 시작한다. 코드가 바뀌면 “인증은 src/auth.ts에 있다”는 메모가 틀린 말이 된다. 틀린 메모는 메모가 없는 것보다 나쁘다. 에이전트는 그 메모를 믿고 엉뚱한 곳을 고친다. 노트를 최신으로 유지하는 방법은 두 가지다. 매 세션 끝에 바꾼 부분의 메모를 고치는 습관, 그리고 몇 세션마다 노트 전체를 코드와 대조하는 정리. git 기록은 이 문제가 없다. 커밋은 그 시점의 사실이고 다시 쓰이지 않는다.

as+1 = as(1 − c) + u · asc
a: 노트 가운데 아직 맞는 메모의 비율, c: 세션마다 코드 변경으로 틀려지는 비율, u: 바꾼 부분의 메모를 그 세션에 고치는 비율. 정리 주기마다 a를 98%로 되돌린다.

해볼 것: ① 세션마다 메모의 3%가 낡고 그중 절반만 고치면, 정리 없이 30세션 뒤 노트의 3분의 1 이상이 틀린다. ② 갱신률을 100%로 올리면 노트가 낡지 않는다. 바꾼 사람이 그 자리에서 메모를 고치는 것이 가장 싸다. ③ 갱신률 0에서 정리 주기를 5로 두면 톱니 모양이 된다. 정리는 습관을 대신하지 못하고, 사이사이에 틀린 메모가 쌓인다. 정리 하나에 세션 하나의 4분의 1을 쓴다고 셌다.

핵심 정리

  1. 새 세션의 첫 턴들은 재적응에 쓰인다. 인수인계가 없으면 이 비용이 프로젝트 크기와 함께 자라고, 잘못된 추측이 중복 작업을 만든다.
  2. 구조화된 기억 — 기능 목록, 진행 파일, git 기록 — 이 가장 싸고 정확하다. 큰 창은 인수인계를 대신하지 못한다.
  3. 기능 목록은 계약서다. 에이전트는 확인한 뒤에 passes만 바꿀 수 있고, 항목을 지우거나 쉽게 고칠 수 없다.
  4. 노트는 낡는다. 바꾼 부분을 그 자리에서 고치는 습관이 기본이고, 주기적 정리는 보조다. git 기록은 낡지 않는 기억이다.

확인 퀴즈

1. 인수인계 없는 실행이 프로젝트가 커질수록 느려지는 가장 큰 이유는?

재적응 비용이 프로젝트 크기에 비례하면 결국 세션 대부분을 “어디까지 했더라”에 쓴다.

2. 에이전트가 features.json에서 “너무 어려워서” 기능 하나를 지우려 한다. 하네스의 올바른 대응은?

기능 목록은 완료의 정의다. 목록을 줄이는 것은 일을 끝내는 것이 아니라 정의를 바꾸는 것이다.

3. 회귀가 발견되어 이미 통과로 표시된 기능을 다시 실패로 바꾸는 것은?

passes는 확인된 사실이다. 사실이 바뀌었으면 기록도 바뀌어야 다음 세션이 올바른 일을 고른다.

4. 노트를 최신으로 유지하는 가장 싼 방법은?

바꾼 사람이 가장 잘 알고, 가장 적은 비용으로 고칠 수 있다. 전체 정리는 그 습관을 보완한다.
