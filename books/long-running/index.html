장기 실행의 한 바퀴

한 문장으로: 목표를 검사 가능한 기능 목록으로 바꿔 두고(초기화), 세션마다 진행 파일을 읽고(기억), 기능 하나만 골라 만들고(안쪽 루프), 스스로 확인한 뒤(검증) 커밋으로 되돌릴 지점을 남기고(체크포인트), 창이 차면 메모를 남기고 새 창에서 다시 시작한다(바깥 루프). 블록을 누르면 해당 장으로 이동합니다.

이 책의 색 언어

모든 그림과 실험에서 같은 색은 같은 역할을 뜻합니다. 표지 3D 그림의 색도 같습니다.

실행 · 에이전트달리고 있는 에이전트, 안쪽 루프, 진행 중인 작업.
사람 · 감독승인, 개입, 아침 검토, 책임 있는 결정.
컨텍스트 창한 세션이 볼 수 있는 토큰, 압축, 창의 경계.
외부 기억 · 계획진행 파일, 기능 목록, 노트, 계획, git 기록.
검증 · 체크포인트통과한 테스트, 커밋, 저장된 상태, 안정.
비용 · 시간토큰, 돈, 벽시계 시간, 사람의 주의.
실패 · 위험충돌, 표류, 맴돌기, 주입, 되돌릴 수 없는 행동.

숫자로 보는 장기 실행

이 교과서를 끝내면 아래 숫자가 왜 중요한지, 서로 어떻게 얽혀 있는지 설명할 수 있게 됩니다.

0.99100 ≈ 0.37단계마다 99% 성공해도 실수를 고치지 못하면 100단계 실행의 성공 확률은 37% (1장)
≈ 7개월AI가 절반의 확률로 끝내는 과제 길이가 두 배가 되는 데 걸린 시간 (METR, 1장)
Σ = O(n²)매 턴 전체 대화를 다시 읽으면 n턴의 입력 토큰은 n²에 비례해 는다 (9장)
τ ≈ √(2CM)저장 비용 C, 평균 고장 간격 M일 때 체크포인트를 남길 최적 간격 (영의 공식, 5장)
1 − (1 − q)n외부 문서 n개를 읽는 동안 주입 공격을 하나 이상 만날 확률. 오래 돌수록 1에 다가간다 (11장)
× 0.1프롬프트 캐시에서 다시 읽는 입력 토큰의 대략적인 가격 배율. 긴 실행의 비용을 바꾼다 (9장)
1 세션 = 1 기능한 번에 다 하려다 창이 끝나면 반쯤 만든 코드만 남는다. 하나씩 끝내고 커밋한다 (2장)
