에이전틱 엔지니어링의 한 바퀴

한 문장으로: 의도를 명세로 굳히고(명세), 필요한 맥락만 골라 주고(컨텍스트), 에이전트가 만든 코드를 기계가 먼저 거르고(검증) 사람이 읽고 책임진 뒤(리뷰) 되돌릴 수 있게 남긴다(체크포인트). 바이브 코딩은 이 가운데 몇 칸을 건너뛰는 것입니다. 어느 칸을 건너뛰어도 되는지가 전략입니다. 블록을 누르면 해당 장으로 이동합니다.

0.920 ≈ 0.12변경 하나가 90% 확률로 멀쩡해도, 읽지 않고 스무 번 수락하면 모두 멀쩡할 확률은 12% (2장)
≈ 7개월AI가 절반의 확률로 끝내는 과제 길이가 두 배가 되는 데 걸린 시간 (METR, 6장)
400줄한 번에 리뷰하는 코드가 이보다 길어지면 결함을 찾는 효율이 뚝 떨어진다 (6·7장)
−19% · +20%한 무작위 실험에서 숙련 개발자는 AI 도구로 19% 느려졌지만, 스스로는 20% 빨라졌다고 느꼈다 (7장)
L = λW에이전트를 늘려 PR 도착률 λ를 높이면 리뷰 대기열 L이 불어난다. 병목은 사람이다 (8장)
≈ 1 / 5한 연구에서 코드 생성 모델이 추천한 패키지 다섯 개 중 하나꼴이 존재하지 않는 이름이었다 (10장)
Q × R바이브를 허용할지는 품질 요구와 폭발 반경의 곱으로 정한다. 둘 다 낮으면 바이브, 둘 다 높으면 엔지니어링 (1·12장)
