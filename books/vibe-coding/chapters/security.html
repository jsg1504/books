Chapter 10

보안과 공급망

바이브 코딩의 가장 비싼 사고는 대개 보안 사고다. API 키가 프런트엔드 코드에 박혀 배포되고, 데이터베이스가 누구나 읽을 수 있게 열리고, 에이전트가 존재하지도 않는 패키지를 설치하려 한다. 마지막 것은 새로운 공격의 문이 되었다. 공격자가 그 이름을 먼저 등록해 두면 되기 때문이다. 그리고 에이전트에게 명령 실행 권한을 통째로 주는 자동 승인 모드는, 편리한 만큼 사고의 반경을 넓힌다. 이 장에서는 AI 코딩이 만든 세 가지 보안 문제를 시뮬레이션으로 본다.

  • 패키지 환각과 슬롭스쿼팅의 원리를 설명하고, 설치 관문의 어떤 방어가 실제로 효과가 있는지 구분할 수 있다.
  • 패키지 설치 요청에서 위험 신호(신생, 낮은 다운로드, 설치 스크립트, 오타 이름, 사내 이름)를 알아볼 수 있다.
  • 에이전트 권한 설정이 만드는 폭발 반경을 그리고, 확인 피로와 위험 사이에서 설정을 고를 수 있다.

지어낸 패키지, 먼저 등록한 공격자

코드 생성 모델은 가끔 존재하지 않는 패키지를 자신 있게 import한다. 2024–2025년에 발표된 한 연구는 여러 코드 생성 모델이 만든 코드 샘플 수십만 개를 분석해, 추천된 패키지 다섯 개 중 하나꼴(약 20%)이 실제로 없는 이름이라고 보고했다. 상용 모델은 그 비율이 훨씬 낮았고, 공개 모델은 더 높았다. 더 중요한 발견은 같은 프롬프트에서 같은 가짜 이름이 반복해서 나온다는 점이다. 반복되는 이름은 예측할 수 있고, 예측할 수 있는 이름은 공격자가 미리 등록할 수 있다. 이것을 슬롭스쿼팅slopsquatting이라고 부른다.

설치 요청 심사

에이전트가 “이 패키지를 설치할게요”라고 할 때 사람이 볼 것은 몇 가지뿐이다. 언제 생겼나, 얼마나 쓰이나, 소스 저장소가 있나, 설치 스크립트가 있나, 그리고 이름이 유명한 패키지와 한 글자 다르거나, 우리 회사 내부 패키지 이름과 같지 않은가. 마지막 경우를 의존성 혼동(dependency confusion)이라 부른다. 아래 카드의 패키지 중 일부는 이 게임을 위해 지어낸 가상의 이름이다.

자동 승인의 폭발 반경

코딩 에이전트는 파일을 고치고 셸 명령을 실행한다. 매 행동마다 사람에게 확인을 받으면 안전하지만 피곤하다. 확인 요청이 한 시간에 수십 번 오면 사람은 읽지 않고 “허용”을 누르게 된다(확인 피로). 그래서 많은 사람이 자동 승인auto-approve 모드를 켠다. 문제는 에이전트가 무엇을 할 수 있느냐다. 에이전트가 읽은 웹 페이지나 이슈 본문에 숨은 지시(프롬프트 주입)가 있으면, 그 지시는 에이전트의 권한으로 실행된다. 폭발 반경은 에이전트에게 준 권한이 정한다.

권한 설계의 원칙① 에이전트는 운영 자격 증명을 갖지 않는다. 운영 배포는 파이프라인이 한다. ② 셸 명령은 컨테이너나 샌드박스 안에서. ③ 네트워크는 필요한 도메인(패키지 레지스트리 등)만. ④ 자동 승인은 허용 목록(테스트·린트·빌드 명령)부터 시작한다.

폭발 반경 — 권한과 승인 방식의 조합

닿는 가장 바깥 고리—
세션 100개당 기대 피해—
시간당 확인 요청—
확인이 실제로 막는 비율—
해볼 것: ① “전부 자동”에 운영 DB 자격 증명을 켜 보자. 고리가 운영 데이터까지 닿고 기대 피해가 치솟는다. ② “매번 확인”으로 바꾸면 피해가 줄 것 같지만, 시간당 확인 요청이 많아 확인 피로로 막는 비율이 떨어진다. 권한이 많을수록 확인이 무력해진다. ③ 운영·클라우드 키를 끄고, 샌드박스를 켜고, “허용 목록만 자동”으로 두자. 요청도 적고 피해도 작다. 안전은 확인 버튼이 아니라 권한의 크기에서 나온다.

핵심 정리

  1. 모델은 없는 패키지를 지어내고, 같은 가짜 이름을 반복한다. 공격자는 그 이름을 먼저 등록한다(슬롭스쿼팅).
  2. 존재 확인은 슬롭스쿼팅을 막지 못한다. 나이·다운로드 검사, 허용 목록, 비밀 없는 샌드박스를 겹쳐 쓴다.
  3. 설치 요청에서는 신생 여부, 사용량, 소스 저장소, 설치 스크립트, 오타 이름, 사내 이름 충돌을 본다.
  4. 자동 승인의 위험은 권한의 크기가 정한다. 확인 요청이 많으면 사람은 읽지 않는다. 권한을 줄이고 샌드박스에 가두는 것이 먼저다.

확인 퀴즈

1. 에이전트가 설치하려는 패키지가 레지스트리에 존재하는지만 확인하면 슬롭스쿼팅을 막을 수 있을까?

슬롭스쿼팅의 정의가 가짜 이름을 실제로 등록하는 것이다. 존재 확인은 오히려 통과시킨다.

2. 다음 중 설치 요청에서 가장 강한 위험 신호는?

신생·무사용·출처 불명·설치 시 코드 실행. 공격용 패키지의 전형적인 모습이다.

3. 회사 내부 패키지 이름이 @acme/auth인데 에이전트가 공개 레지스트리의 같은 이름을 설치하려 한다. 이것은?

공개 레지스트리에 사내 이름을 등록해 빌드가 그것을 받게 만드는 공격이다.

4. 에이전트 권한 설계에서 가장 먼저 할 일은?

확인은 피로로 무력해진다. 할 수 있는 일 자체를 줄이는 것이 폭발 반경을 줄인다.
