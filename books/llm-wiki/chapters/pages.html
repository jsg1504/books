Chapter 04

페이지 설계: 원자성과 구조

위키의 품질은 결국 페이지 하나하나의 품질이다. 에이전트가 쓰는 페이지는 사람이 읽기 좋아야 하고, 동시에 다음 세션의 에이전트가 찾고, 열고, 믿고, 고치기 좋아야 한다. 이 장에서는 위키에 어떤 종류의 페이지가 있는지, 한 페이지에 얼마만큼 담아야 하는지, 페이지 맨 위에 어떤 메타데이터를 적어야 하는지를 다룬다. 페이지 크기에는 최적점이 있고, 그 최적점은 검색 도구에 따라 움직인다.

  • 요약, 엔티티, 개념, 분석 페이지를 구별하고 각각에 무엇을 담는지 말할 수 있다.
  • 한 페이지 한 생각의 원자성이 링크, 재사용, 갱신에 주는 이점을 설명할 수 있다.
  • 페이지 크기가 질의와 수집 비용에 주는 영향을 계산하고 최적 크기를 찾을 수 있다.

네 종류의 페이지

카파시의 메모와 실제 위키들을 보면 페이지는 대개 네 종류로 나뉜다. 종류마다 폴더를 따로 두면 에이전트도 사람도 길을 잃지 않는다.

요약 페이지 · sources/원천 하나에 하나. 무엇을 주장했고, 근거는 무엇이며, 위키의 어느 페이지에 영향을 줬는지. 원천 경로를 머리말에 적는다. 다른 페이지들의 출처 링크가 여기로 온다.
엔티티 페이지 · entities/사람, 조직, 제품, 장소처럼 이름 있는 대상 하나. 사실, 연표, 관계. 원천이 들어올 때마다 조금씩 자란다.
개념 페이지 · concepts/기법, 이론, 용어처럼 추상적인 생각 하나. 한 문장 정의로 시작하고, 여러 원천의 관점을 모은다. 위키의 뼈대다.
분석 페이지 · analyses/비교표, 종합, 개관, 질의의 답. 원천이 아니라 위키 자체에서 태어난다. 좋은 질문의 답을 저장한 것(6장)이 대표적이다.

구분의 핵심은 무엇이 바뀌면 페이지가 바뀌는가다. 요약 페이지는 원천이 고정이므로 거의 바뀌지 않는다. 엔티티와 개념 페이지는 새 원천마다 갱신된다. 분석 페이지는 그것이 기댄 개념 페이지가 바뀌면 낡는다. 그래서 분석 페이지의 머리말에는 무엇을 근거로 언제 썼는지를 꼭 남긴다(8장의 린트가 이것을 쓴다).

한 페이지에 한 생각

사회학자 니클라스 루만은 수십 년 동안 메모 카드 9만 장으로 이루어진 제텔카스텐Zettelkasten을 꾸렸다. 규칙은 단순했다. 카드 한 장에 생각 하나, 카드마다 고유 번호, 카드 사이에 참조. 이것이 원자적 노트atomic note다. LLM 위키에도 그대로 통한다. 한 페이지에 한 생각만 있으면 링크가 정확해진다(“BM25 페이지”를 가리키면 정말 BM25만 나온다). 재사용이 쉬워진다(같은 개념 페이지를 열 개의 분석이 인용한다). 갱신이 안전해진다(새 원천이 BM25를 고칠 때 임베딩 설명을 건드릴 일이 없다).

그렇다고 무한히 쪼갤 수는 없다. 페이지가 작아지면 개수가 늘고, 개수가 늘면 색인이 길어지고, 질문 하나에 열어야 하는 페이지도 많아진다. 페이지 하나를 열 때마다 머리말, 제목, 도구 호출 같은 고정 비용도 붙는다. 반대로 페이지가 크면 질문과 상관없는 내용을 함께 읽고, 수집할 때 큰 페이지를 통째로 다시 써야 한다. 최적 크기가 있다.

머리말과 페이지 형식

페이지 맨 위의 YAML 머리말frontmatter은 기계를 위한 칸이다. 사람은 본문을 읽지만 에이전트와 도구는 머리말을 먼저 본다. 유형, 출처, 갱신일, 태그를 적어 두면 옵시디언의 Dataview 같은 플러그인으로 “최근 30일에 갱신된 개념 페이지”를 표로 뽑을 수 있고, 린트는 “출처가 하나뿐인 주장”이나 “근거 페이지보다 오래된 분석”을 찾을 수 있다. 아래에서 페이지 한 장을 고쳐 가며 각 규칙이 무엇을 바꾸는지 보자.

핵심 정리

  1. 페이지는 요약 · 엔티티 · 개념 · 분석의 네 종류로 나누고, 종류마다 폴더를 둔다. 무엇이 바뀌면 그 페이지가 바뀌는지가 기준이다.
  2. 한 페이지 한 생각(원자성)은 링크를 정확하게, 재사용을 쉽게, 갱신을 안전하게 만든다.
  3. 페이지 크기에는 최적점이 있다. 평평한 색인은 큰 페이지 쪽으로, 검색 도구는 작은 페이지 쪽으로 최적점을 옮긴다.
  4. 머리말에는 유형, 출처, 갱신일을 적는다. 사람이 아니라 에이전트와 린트를 위한 칸이다.

확인 퀴즈

1. “트랜스포머와 상태 공간 모델의 긴 문맥 성능 비교” 페이지는 어느 종류인가?

두 개념 페이지와 여러 원천을 엮은 비교다. 근거 페이지가 바뀌면 낡으므로 머리말에 근거와 작성일을 남긴다.

2. 원자적 페이지의 이점이 아닌 것은?

반대다. 페이지가 작을수록 개수가 늘어 평평한 색인은 길어진다. 그래서 원자적 위키는 검색 도구와 짝을 이룬다.

3. 검색 도구를 붙이면 최적 페이지 크기가 작아지는 이유는?

평평한 색인은 페이지마다 한 줄씩 늘어난다. 검색 도구는 상위 결과 몇 개만 돌려주므로 페이지 수와 거의 무관하다.

4. 분석 페이지의 머리말에 “근거 페이지와 작성일”을 남기는 가장 큰 이유는?

분석은 위키에서 태어나므로 위키가 바뀌면 낡는다. 근거의 갱신일이 분석의 작성일보다 늦으면 다시 볼 후보다.
