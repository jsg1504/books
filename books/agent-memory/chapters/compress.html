Chapter 03

압축과 요약

윈도우가 차면 무언가를 버려야 한다. 가장 흔한 방법은 지난 대화를 요약해 짧게 바꾸는 압축compaction이다. 요약은 공간을 되찾아 주지만 손실이 있고, 거듭할수록 손실이 쌓인다. 이 장에서는 요약이 무엇을 잃는지, 언제 압축해야 하는지, 그리고 무엇을 요약에 맡기지 말아야 하는지를 다룬다.

  • 요약을 반복할 때 사실의 생존 확률이 곱으로 줄어드는 이유와, 수치·이름 같은 세부가 특히 잘 사라지거나 왜곡되는 이유를 설명할 수 있다.
  • 압축 임계와 요약 비율이 비용과 정보 보존에 미치는 영향을 예측할 수 있다.
  • 롤링 요약, 계층 요약, 고정 메모의 구조를 비교할 수 있다.
  • 제한된 예산 안에서 미래에 필요할 정보를 고르는 기준을 세울 수 있다.

롤링 요약의 구조

가장 단순한 압축은 롤링 요약이다. 컨텍스트에 “지금까지의 요약” 한 덩어리와 최근 턴 원문을 함께 두고, 원문이 넘치면 오래된 턴을 요약에 흡수시킨다. 새 요약은 이전 요약 + 밀려난 턴을 입력으로 다시 만들어진다. 즉 초반 대화의 사실은 압축이 일어날 때마다 다시 요약된다. 이것이 재귀 요약recursive summarization이다.

요약의 전화 게임

요약 모델은 “중요해 보이는 것”을 남긴다. 목표나 사람 이름처럼 두드러지는 사실은 잘 살아남지만, 브랜치 이름, 숫자 한도, 빌드 명령 같은 세부는 쉽게 빠진다. 더 나쁜 경우는 왜곡이다. “6월 30일”이 “6월 3일”이 되거나 “200ms”가 “2초”가 되면, 차라리 잊은 것보다 해롭다. 틀린 기억을 자신 있게 쓰기 때문이다.

아래 실험에서 사실마다 두드러짐(salience)이 정해져 있다. 한 번 요약할 때 생존 확률은 p = s + (1 − s)·c다. s는 두드러짐, c는 요약 비율(원문 대비 요약 길이)이다. 살아남은 사실도 일정 확률로 왜곡된다.

언제 압축할 것인가

압축 임계 θ(윈도우의 몇 %가 차면 압축할지)는 두 가지를 맞바꾼다. θ가 낮으면 압축이 잦아 요약을 많이 거치므로 정보가 더 많이 사라진다. θ가 높으면 압축은 드물지만 매 턴 긴 입력을 보내므로 비용이 커지고, 2장에서 본 어텐션 희석도 심해진다. 요약 자체도 모델 호출이라 비용이 든다.

계층 요약과 고정 메모

재귀 요약의 손실을 줄이는 방법은 두 가지다. 첫째, 계층 요약hierarchical summary은 원본을 버리지 않고 외부 저장소에 둔 채, 세션 요약 → 일 단위 요약 → 주 단위 요약처럼 해상도가 다른 요약을 쌓는다. 상위 요약이 놓친 세부는 필요할 때 하위 요약이나 원문을 검색해 되찾는다. 둘째, 고정 메모는 목표, 제약, 결정, 할 일처럼 잃으면 안 되는 것을 요약과 별도로 구조화해 두는 것이다.

핵심 정리

  1. 롤링 요약은 이전 요약을 다시 요약한다. 한 번의 생존 확률이 p면 k번 뒤에는 pk.
  2. 요약은 두드러지지 않는 세부(숫자, 이름, 명령)부터 잃고, 때로 왜곡한다. 틀린 기억은 빠진 기억보다 해롭다.
  3. 압축 임계는 정보 손실(낮은 θ)과 비용·희석(높은 θ)을 맞바꾼다.
  4. 원문을 외부 저장소에 남기는 계층 요약과, 요약하지 않는 고정 메모가 손실을 줄인다. 다시 얻을 수 있는 것은 위치만, 다시 얻을 수 없는 것은 내용을 남긴다.

확인 퀴즈

1. 요약 한 번의 생존 확률이 0.8인 사실이 롤링 요약을 5번 거친 뒤 남아 있을 확률은?

0.85 ≈ 0.328.

2. 요약 과정에서 “마감 6월 30일”이 “마감 6월 3일”로 바뀌었다. 이것이 단순 누락보다 위험한 이유는?

빠진 정보는 다시 묻거나 찾을 계기가 되지만, 왜곡된 정보는 그럴듯해서 검증 없이 쓰인다.

3. 다음 세션에 가져갈 메모로 가장 적절하지 않은 것은?

파일은 저장소에서 다시 읽을 수 있다. 메모에는 경로와 핵심 변경점만 남기면 된다. 시도와 결정은 다시 얻을 수 없다.

4. 압축 임계 θ를 0.95로 높였을 때 일어나지 않는 일은?

θ가 높으면 압축이 드물어 요약을 덜 거친다. 대신 긴 입력의 비용과 희석을 감수한다.
