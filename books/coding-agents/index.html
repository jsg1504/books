코딩 에이전트는 무엇을 하는가

한 문장으로: 언어 모델이 도구를 써서 저장소를 읽고, 고치고, 실행해 본 결과를 다시 읽는 일을 끝날 때까지 반복한다. 그 반복의 각 마디가 이 교과서의 목차입니다. 블록을 누르면 해당 장으로 이동합니다.

이 책의 색 언어

모든 그림과 실험에서 같은 색은 같은 종류의 행동을 뜻합니다. 색만 보고도 에이전트가 지금 무엇을 하는지 읽을 수 있게 하려는 약속입니다.

사용자요청, 승인, 중단. 루프 바깥의 사람.
추론모델이 다음 행동을 고르는 순간. 토큰을 생성한다.
읽기 · 검색파일 읽기, grep, 목록 보기. 상태를 바꾸지 않는다.
편집파일을 쓰거나 고친다. 되돌릴 수 있지만 흔적이 남는다.
실행 · 통과명령 실행, 테스트, 빌드. 성공 신호도 이 색이다.
실패 · 위험테스트 실패, 오류, 차단된 행동.

숫자로 보는 코딩 에이전트

이 교과서를 끝내면 아래 숫자가 왜 중요한지, 서로 어떻게 얽혀 있는지 설명할 수 있게 됩니다.

pn단계마다 성공률 p인 일을 피드백 없이 n번 이어 하면 전체 성공률은 기하급수로 떨어진다 — 루프가 필요한 이유 (1장)
≈ 4 글자영어 텍스트에서 토큰 하나가 담는 평균 글자 수의 경험칙. 코드와 한국어는 다르다 (2장)
O(n²)매 턴 대화 전체를 다시 입력하므로, 턴 수 n에 대해 누적 입력 토큰은 대략 제곱으로 자란다 (9장)
1 곳문자열 치환 편집이 성공하려면 찾는 문자열이 파일에서 정확히 한 곳이어야 한다 (5장)
pass@k ↑ · pass^k ↓k번 중 한 번이라도 성공할 확률은 오르고, k번 모두 성공할 확률은 떨어진다 (9장)
±4.4%p500문제 벤치마크에서 성공률 50%의 95% 신뢰구간 반폭 — 1~2%p 차이는 잡음일 수 있다 (9장)
