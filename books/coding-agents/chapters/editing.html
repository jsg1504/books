Chapter 05

편집과 패치

원인을 찾았다면 이제 고칠 차례다. 그런데 모델이 “파일을 고친다”는 것은 정확히 무엇일까? 모델은 텍스트만 만들 수 있으므로, 하네스와 약속한 편집 형식edit format으로 변경을 기술해야 한다. 파일 전체를 다시 쓸 수도, 바꿀 부분만 지정할 수도, diff를 쓸 수도 있다. 형식마다 실패하는 방식과 비용이 다르다.

  • 전체 재작성, 문자열 치환, unified diff, 줄 번호 편집의 차이를 설명할 수 있다.
  • 문자열 치환이 실패하는 두 가지 경우(불일치, 중복 일치)를 진단하고 고칠 수 있다.
  • diff의 맥락 줄과 줄 번호가 파일 변경에 어떻게 반응하는지 이해한다.
  • 파일 크기와 변경 크기에 따른 편집 형식별 출력 토큰을 비교할 수 있다.

같은 수정, 네 가지 표현

세션 만료 버그를 고치는 한 줄짜리 수정을 네 가지 형식으로 써 보자.

① 전체 재작성파일 전체 출력

  const now = Date.now();
    return session.expires * 1000 > now;}

전체 재작성파일 크기에 비례 (크다)긴 파일에서 관련 없는 부분을 빠뜨리거나 바꿈새 파일, 아주 작은 파일, 전면 개편
문자열 치환변경 + 고유하게 만드는 맥락공백까지 정확히 일치하지 않음 · 여러 곳에 일치대부분의 국소 수정 (많은 코딩 에이전트의 기본)

핵심 차이는 위치를 무엇으로 지정하느냐다. 줄 번호는 위치를 숫자로, 문자열 치환과 diff는 위치를 내용으로 지정한다. 내용으로 지정하면 파일이 조금 바뀌어도 찾아갈 수 있지만, 내용이 정확히 맞아야 한다.

문자열 치환 편집기

문자열 치환은 규칙이 단순하다. old_string이 파일에서 정확히 한 곳 일치하면 그 자리를 new_string으로 바꾼다. 0곳이면 “찾을 수 없음”, 2곳 이상이면 “고유하지 않음”으로 거절한다. 거절은 실패가 아니라 안전장치다. 잘못된 곳을 고치는 것보다 다시 시도하는 편이 낫다.

diff는 움직이는 파일 위에 놓인다

unified diff의 hunk는 @@ -시작,길이 +시작,길이 @@ 헤더와, 바뀌지 않는 맥락 줄(앞에 공백), 지울 줄(-), 넣을 줄(+)로 이루어진다. 패치를 적용하는 프로그램은 헤더의 줄 번호에서 맥락 줄을 찾는다. 그런데 그 사이 파일이 바뀌었다면? 다른 편집이 위쪽에 줄을 추가했거나, 동료가 커밋을 올렸다면?

대부분의 패치 도구는 헤더 위치에서 맥락이 안 맞으면 근처를 찾아본다(오프셋). 그래도 없으면 맥락 줄 일부를 무시하고 맞춰 보기도 한다(퍼지). 아래 실험에서 hunk 위쪽에 줄을 끼워 넣고, 맥락 줄을 바꿔 가며 적용 결과를 보자.

편집 형식의 비용

출력 토큰은 입력 토큰보다 비싸고(보통 몇 배), 생성 속도도 느리다. 그래서 편집 형식은 비용과 지연에 직결된다. 파일 길이 L줄, 변경 c줄이 m군데에 흩어져 있다고 하자. 줄당 토큰을 τ라 하면 대략:

전체 ≈ τL,   치환 ≈ τ(2c + 2um),   diff ≈ τ(2c + 6m) + 헤더,   줄번호 ≈ τc + 작은 상수·m
u: old_string을 고유하게 만들기 위해 덧붙이는 맥락 줄 수(앞뒤 각각). diff의 6m은 hunk마다 앞뒤 3줄씩의 맥락. 치환과 diff의 2c는 지울 내용과 넣을 내용을 모두 쓰기 때문이다.

편집 직후에 확인한다편집이 “적용되었다”는 것은 텍스트가 바뀌었다는 뜻일 뿐, 코드가 옳다는 뜻이 아니다. 하네스나 에이전트는 편집 직후 포매터·린터·타입 검사기를 돌려 문법 오류를 바로 잡는다. 이 빠른 신호가 다음 장의 주제인 피드백 루프의 첫 단계다.

핵심 정리

  1. 편집 형식은 위치를 지정하는 방식이 다르다. 줄 번호는 숫자로, 치환과 diff는 내용으로 위치를 찾는다.
  2. 문자열 치환은 정확히 한 곳 일치할 때만 적용된다. 불일치는 공백·들여쓰기, 중복은 맥락 부족이 원인인 경우가 많다.
  3. diff는 오프셋·퍼지로 움직이는 파일에 적응하지만, 넓은 탐색과 퍼지는 엉뚱한 곳에 적용될 위험을 키운다.
  4. 출력 토큰은 비싸다. 국소 수정에는 치환·diff, 전면 개편에는 전체 재작성이 유리하다.

확인 퀴즈

1. 문자열 치환이 “old_string이 3곳에서 일치”로 거절되었다. 올바른 대응은?

맥락을 덧붙여 한 곳만 일치하게 만든다. 세 곳 모두를 바꾸는 것이 의도라면 replace_all을 쓴다.

2. 같은 파일에 연달아 두 번 편집할 때 줄 번호 편집이 특히 위험한 이유는?

내용으로 위치를 찾는 형식은 줄 이동에 강하지만, 숫자로 찾는 형식은 조용히 엉뚱한 줄을 바꾼다.

3. 3,000줄 파일에서 두 줄을 고친다. 출력 토큰이 가장 많은 형식은?

전체 재작성은 바꾸지 않는 2,998줄까지 다시 출력한다.
