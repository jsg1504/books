Chapter 06

실행과 피드백

1장에서 피드백 루프의 힘은 실패를 볼 수 있는 능력(감지율 d)에서 나온다는 것을 계산했다. 코딩 에이전트에게 그 눈은 컴파일러, 린터, 타입 검사기, 그리고 무엇보다 테스트다. 이 장에서는 테스트 결과를 보며 고쳐 나가는 디버깅 루프를 애니메이션으로 보고, 반복 횟수의 분포를 계산하고, 신호를 흐리는 불안정한 테스트와 신호를 속이는 행동을 다룬다.

  • 피드백 신호들을 속도와 충실도로 비교하고 어떤 순서로 쓰는 것이 좋은지 말할 수 있다.
  • 수정 성공률과 회귀 확률이 디버깅 루프의 수렴에 미치는 영향을 설명할 수 있다.
  • 반복 횟수 분포의 꼬리가 예산 설정에 왜 중요한지 이해한다.
  • 불안정한(flaky) 테스트의 거짓 경보율을 계산하고, 재시도의 효과와 비용을 비교할 수 있다.
  • “테스트 통과”와 “문제 해결”이 다를 수 있는 경우를 알아본다.

테스트는 에이전트의 눈이다

에이전트가 받을 수 있는 피드백은 여러 층이 있다. 빠른 신호는 싸지만 얕고, 깊은 신호는 정확하지만 느리다. 좋은 루프는 빠른 신호로 사소한 실수를 즉시 거르고, 깊은 신호로 최종 확인을 한다.

디버깅 루프를 지켜보기

실패하는 테스트가 여럿 있는 상태에서 에이전트가 하나씩 고쳐 나간다고 하자. 한 번의 반복은 “실패 메시지 읽기 → 원인 추정 → 편집 → 테스트 재실행”이다. 수정은 확률 pfix로 성공하고, 같은 원인을 공유하는 이웃 테스트도 함께 고쳐질 수 있다. 반면 확률 preg로 지금까지 통과하던 테스트 하나를 깨뜨린다(회귀regression).

몇 번 만에 끝나는가: 반복 횟수의 분포

불안정한 테스트: 흐려진 눈

코드가 그대로인데 가끔 실패하는 테스트를 불안정한 테스트flaky test라 한다. 타이밍, 네트워크, 실행 순서, 시각에 의존하는 테스트가 흔한 원인이다. 사람에게는 귀찮은 정도지만 에이전트에게는 위험하다. 에이전트는 실패를 보면 고치려 들기 때문이다 — 멀쩡한 코드를 “고치거나”, 자기 변경이 원인이라고 오해한다.

테스트 k개가 각각 확률 f로 무작위 실패한다면, 스위트 한 번이 “빨간색”이 될 거짓 경보 확률과, 실패 시 r번 재시도해 한 번이라도 통과하면 통과로 보는 경우의 확률은 다음과 같다.

P거짓 경보 = 1 − (1 − f)k   →   P재시도 = 1 − (1 − fr+1)k
불안정한 테스트 20개가 각각 2%로 실패하면 스위트의 33%가 빨간색이다. 재시도 2번이면 0.016%로 떨어진다. 대신 진짜로 불안정한 동작(경쟁 상태 같은 실제 버그)도 함께 가려진다.

통과는 해결이 아니다

피드백 신호가 강력한 만큼, 신호 자체를 최적화하는 실패도 생긴다. 테스트를 통과시키라는 목표만 주어지면, 원인을 고치는 대신 테스트를 약하게 만들거나 특정 입력만 특별 처리하는 해법이 “통과”로 보일 수 있다.

피해야 할 “해결”들diff
# ✗ 1. 테스트를 건너뛰게 만든다
-test("fresh session is active", () => {+test.skip("fresh session is active", () => {
# ✗ 2. 기대값을 실제 출력에 맞춘다
-  expect(isActive(s)).toBe(true);+  expect(isActive(s)).toBe(false);
# ✗ 3. 테스트 입력만 특별 처리한다
+  if (process.env.NODE_ENV === "test") return true;
# ✓ 원인을 고친다: 단위를 맞춘다
-  return session.expires > now;+  return session.expires * 1000 > now;

핵심 정리

  1. 피드백 신호는 빠르고 얕은 것(구문·린트·타입)부터 느리고 깊은 것(통합 테스트·리뷰)까지 사다리를 이룬다. 편집 직후엔 아래부터, 완료 전엔 위까지.
  2. 디버깅 루프의 수렴은 수정 성공률과 회귀 확률의 줄다리기다. 회귀를 잡으려면 기존 테스트도 다시 돌려야 한다.
  3. 반복 횟수 분포는 꼬리가 길다. 예산은 평균이 아니라 원하는 백분위로 잡는다.
  4. 불안정한 테스트는 거짓 경보를 만들어 에이전트를 오도한다. 재시도는 증상을 가리고, 격리·수정이 근본 대책이다.
  5. 테스트 통과 ≠ 문제 해결. 테스트를 바꾸는 변경은 특별히 의심한다.

확인 퀴즈

1. 편집 직후 가장 먼저 돌리기 좋은 신호는?

빠른 신호로 사소한 실수를 즉시 걸러 내면, 비싼 테스트를 돌리는 횟수가 준다.

2. 불안정한 테스트 10개가 각각 5%로 실패한다. 재시도 없이 스위트가 빨간색일 확률은?

1 − 0.9510 ≈ 0.40.

3. 에이전트가 실패하던 테스트의 기대값을 바꿔서 통과시켰다. 적절한 판단은?

테스트 수정은 정당한 경우도 있지만, 근거 없이 기대값을 바꾸는 것은 신호를 속이는 대표적인 패턴이다.

4. 평균 8회에 끝나는 디버깅 루프에 예산 8회를 주면?

반복 횟수 분포는 오른쪽 꼬리가 길어 평균이 중앙값보다 크다. 평균 예산으로는 많은 실행이 끝나지 못한다.
