Chapter 04

코드베이스 탐색

에이전트는 저장소를 모르는 채로 일을 시작한다. 사람 개발자가 처음 보는 프로젝트에서 그러듯, 디렉터리 구조를 훑고, 이름으로 찾고, 필요한 부분만 읽는다. 다만 에이전트에게는 읽는 모든 것이 컨텍스트 토큰이라는 비용이 된다. 이 장은 적게 읽고 정확히 찾는 법을 다룬다.

  • glob, grep, 범위 읽기, 심볼 탐색, 의미 검색의 쓰임새와 비용을 비교할 수 있다.
  • 정규식 검색 결과의 정밀도(일치 수)를 조절하는 방법을 안다.
  • 저장소 크기와 키워드의 흔함에 따라 탐색 전략의 비용이 어떻게 달라지는지 설명할 수 있다.
  • 저장소 지도(심볼 개요)가 전체 내용 대비 얼마나 작은지, 언제 유용한지 말할 수 있다.

탐색 전략 경주

버그가 있는 파일 하나를 찾는 세 가지 전략을 비교해 보자. 각 점은 파일 하나, 점의 크기는 파일 크기다. 에이전트가 읽은 파일은 파랗게 변하고, 목표 파일을 찾으면 초록 링이 생긴다.

  • 차례로 읽기 — 디렉터리 순서대로 파일을 연다. 아무 정보 없이 시작한 경우의 기준선.
  • grep 먼저 — 키워드로 후보 파일을 추린 뒤(작은 비용) 후보만 읽는다. 키워드가 흔할수록 후보가 많다.
  • 의미 검색 — 질의와 비슷한 순서로 파일을 정렬해 위에서부터 읽는다. 질의 품질이 낮으면 목표의 순위가 밀린다.

저장소 지도

파일을 다 읽을 수는 없지만, 각 파일에 어떤 함수와 클래스가 있는지만 요약한 지도는 훨씬 작다. 함수 이름과 시그니처만 남기면 원래 크기의 수 퍼센트로 줄어든다. 일부 에이전트는 이런 저장소 지도repo map를 컨텍스트에 넣어 어디를 볼지 고르는 데 쓴다. 아래 트리맵에서 사각형의 넓이는 파일의 토큰 수다. 파일을 눌러 지도에 담기는 내용을 확인해 보자.

핵심 정리

  1. 탐색은 깔때기다: 목록·glob → grep → 범위 읽기. 위는 싸고 넓고, 아래는 비싸고 구체적이다.
  2. grep의 성패는 패턴의 정밀도에 달렸다. 흔한 단어는 결과를 폭발시킨다. 경로 필터와 구체적인 패턴으로 좁힌다.
  3. 정확한 단어를 알면 grep, 개념만 알면 의미 검색, 호출 관계는 심볼 탐색. 실무에서는 섞어 쓴다.
  4. 심볼 지도는 전체 내용의 수 퍼센트로 저장소의 윤곽을 보여 준다. 큰 저장소에서는 그마저 골라 넣어야 한다.

확인 퀴즈

1. 테스트 로그에 TypeError: cannot read 'expiresAt' of undefined가 찍혔다. 가장 효율적인 첫 탐색은?

정확하고 드문 식별자를 알고 있으므로 grep이 몇 줄 안에 후보를 준다.

2. grep 결과가 2,000줄이 나왔다. 가장 적절한 다음 행동은?

결과 폭발은 패턴이 너무 넓다는 신호다. 좁혀서 다시 묻는 편이 훨씬 싸다.

3. “사용자 권한을 확인하는 코드가 어디 있지?”처럼 정확한 단어를 모를 때 유리한 것은?

개념 수준의 질문은 의미 검색이나 구조(예: src/auth/)로 방향을 잡은 뒤 grep으로 확인한다.
