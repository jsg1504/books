Chapter 09

오류 처리 · 재시도 · 관측성

에이전트 실행 하나는 수십 번의 모델 호출과 도구 실행으로 이루어진다. 그중 하나만 실패해도 전체가 무너질 수 있다. 하네스는 실패를 세 겹으로 다룬다. 알아채고(피드백과 검증), 다시 하고(재시도와 폴백), 기록한다(트레이스). 이 장에서는 실패가 단계 수만큼 곱해지는 효과, 재시도가 서버를 더 아프게 만드는 경우, 트레이스로 느리고 비싼 곳을 찾는 법을 실험한다.

  • 단계별 성공률이 전체 성공률로 곱해지는 효과와, 감지·재시도가 그것을 바꾸는 방식을 계산할 수 있다.
  • 오류를 일시적·영구적·모델 출력 오류로 나누고 각각의 처리 방법을 말할 수 있다.
  • 지수 백오프에 지터가 필요한 이유를 동시 재시도 폭주로 설명할 수 있다.
  • 트레이스와 스팬으로 한 실행의 지연과 비용을 분해할 수 있다.

실패는 곱해진다

한 단계를 성공할 확률이 p이고 단계가 n개라면, 실패를 바로잡을 방법이 없을 때 전체 성공 확률은 pn이다. 95%짜리 단계 20개면 36%, 50개면 8%다. 긴 작업에서 에이전트가 무너지는 이유의 상당 부분이 이 곱셈이다. 하네스는 두 가지로 곱셈을 끊는다. 실패를 알아채게 하고(테스트, 타입 검사, 스키마 검증, 명확한 오류 메시지), 알아챈 실패를 다시 시도하게 한다.

P단계 = p · Σi=0..r ((1 − p) d)i   ·   P전체 = P단계n
d: 실패를 알아챌 확률(감지율), r: 최대 재시도 횟수. 알아채지 못한 실패는 조용히 다음 단계로 넘어가 결국 틀린 결과가 된다. 감지율이 낮으면 재시도를 아무리 늘려도 소용없다 — 재시도보다 감지가 먼저다.

재시도와 백오프

모든 오류를 다시 시도하면 안 된다. 오류의 종류에 따라 처리가 다르다.

종류예하네스의 처리
일시적요청 한도 초과(429), 서버 과부하·5xx, 네트워크 타임아웃백오프하며 자동 재시도. 응답의 Retry-After를 존중. 계속 실패하면 다른 모델이나 지역으로 폴백
영구적잘못된 요청(400), 인증 실패(401), 컨텍스트 초과재시도 금지. 입력을 고치거나(압축 등) 사용자에게 알림
모델 출력 오류스키마에 맞지 않는 도구 인자, 없는 도구 이름오류를 tool_result로 모델에게 되먹여 스스로 고치게 함(4장)
도구 실행 오류테스트 실패, 파일 없음, 명령 타임아웃정상적인 결과로 모델에게 전달 — 이것이 피드백 루프다

일시적 오류를 재시도할 때 흔한 실수가 즉시 재시도다. 서버가 과부하로 요청을 거절했는데 모든 클라이언트가 바로 다시 보내면 과부하가 더 심해진다. 그래서 실패할 때마다 대기 시간을 두 배로 늘리는 지수 백오프exponential backoff를 쓴다. 그런데 모두가 같은 순간에 실패했다면 모두가 같은 순간(1초, 2초, 4초 뒤)에 다시 몰린다. 대기 시간에 무작위성을 섞는 지터jitter가 이 동기화를 깬다.

관측성: 트레이스로 병목 찾기

“에이전트가 느리다”, “어제보다 비싸다”는 불만에 답하려면 실행 하나를 단계별로 다시 볼 수 있어야 한다. 이것을 위해 하네스는 실행 전체를 트레이스로, 모델 호출·도구 실행·훅·하위 에이전트를 각각 스팬으로 기록한다. 스팬마다 시작·끝 시각, 입력·출력 토큰, 캐시 적중, 오류를 남겨 두면 나중에 지연과 비용을 분해할 수 있다. 아래는 실제와 비슷하게 만든 한 실행의 트레이스다. 막대를 눌러 자세히 보자.

핵심 정리

  1. 실패는 단계 수만큼 곱해진다. 감지가 재시도보다 먼저다. 알아채지 못한 실패는 다시 할 수 없다.
  2. 일시적 오류는 백오프로 재시도하고, 영구적 오류는 재시도하지 않으며, 모델 출력 오류는 모델에게 되먹인다.
  3. 지수 백오프만으로는 동시에 실패한 클라이언트들이 같은 박자로 돌아온다. 지터로 동기화를 깬다.
  4. 트레이스와 스팬으로 한 실행의 지연과 비용을 분해한다. 시간의 병목과 돈의 병목은 다를 수 있다.

확인 퀴즈

1. 단계 성공률 98%인 30단계 작업을 실패 감지 없이 돌리면 전체 성공률은 대략?

0.98³⁰ ≈ 0.545.

2. 401 인증 오류를 받았다. 하네스의 올바른 처리는?

영구적 오류는 다시 보내도 같다. 재시도는 시간과 한도만 낭비한다.

3. 지수 백오프에 지터를 더하는 이유는?

지터는 재시도 시각을 흩어 순간 부하의 봉우리를 없앤다.

4. 에이전트가 느리다는 불만을 받았다. 가장 먼저 할 일은?

병목은 모델이 아니라 도구 실행이나 대기일 수 있다. 측정이 먼저다.
